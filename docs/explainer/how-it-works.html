01

VOICEVOX ってなに？

文章を入力すると、キャラクターの声で読み上げてくれる無料のソフトです。歌を歌わせることもできます。

中身は、役割のちがう 3つのプログラム の組み合わせです。この資料で説明するのは、いちばん左の「エディター」です。

💡

キャラクターの声や絵は、オープンソースとは相性の悪いライセンスを持っていることが多いので、キャラクターを含まない「OSS 版」と、キャラクターを含めた「製品版」を分けて配っています。

02

どこで動くの？

声づくりは あなたのパソコンの中だけ で行われます。エディターとエンジンは、同じパソコンの中で「Web の通信」を使って話しています。

🪟

エディター

Electron というしくみで、Web の技術（HTML・CSS・JavaScript）を使ってデスクトップアプリとして動きます。

🔌

エンジン

エディターがエンジンのプログラムを起動し、--port 50021 のように番号を渡します。番号がふさがっていたら、別の番号を探します。

🌐

ブラウザ版もある

開発やテスト用に、ブラウザだけで動く版もあります。エンジンを起動できないので、すでに動いているエンジンにつなぎます。

03

係の分担

エディターの中は、5つの係 に分かれています。画面の係が直接ファイルやエンジンをさわらず、かならず「記録係」を通す のがルールです。

🖼️

画面係

ボタンやテキスト欄を表示して、押されたら記録係に頼みます。Vue のコンポーネントです。

📒

記録係

今の状態（台本、選んでいる声、設定…）をすべてノートに持ち、変更もここで行います。Vuex のストアです。

☎️

電話係

エンジンへの注文を担当します。注文の書き方は、エンジンの説明書（OpenAPI）から自動で作られます。

🧰

裏方係

ファイルの読み書き、設定の保存、エンジンの起動・終了など、ブラウザだけではできない仕事をします。

🚪

受付（プリロード）

画面側と裏方係の間にある小さな窓口です。決められたお願いだけを通します（11 安全のしくみ）。

コードで見ると：画面係は記録係に「お願い」するだけVue 
// components/Talk/AudioCell.vue（短くしたもの）
const store = useStore();

// テキスト欄の文字が変わったら、記録係にお願いする
await store.actions.COMMAND_CHANGE_AUDIO_ITEM_TEXT({ audioKey, text });

// 記録係のノートを読むのは自由
const audioItem = computed(() => store.state.audioItems[audioKey]);

画面係はエンジンのことを何も知りません。「文字が変わった」と伝えるだけで、エンジンへの注文やノートの書きかえは記録係が引き受けます。こうしておくと、状態が予想外に変わったときの原因を探しやすくなります。

04

声ができるまで

エンジンへの注文は 2回 に分かれています。1回目で「どう読むか」の設計図をもらい、2回目でその設計図から声を作ってもらいます。

コードで見ると：文字が変わったときの記録係store/audio.ts 
// COMMAND_CHANGE_AUDIO_ITEM_TEXT（とても短くしたもの）
async action({ state, actions, mutations }, { audioKey, text }) {
  const query = state.audioItems[audioKey].query;
  // [メモ] を消し、ルビの読みを使った「読む文」を作る
  const yomi = extractYomiText(text, { ... });

  if (query != undefined) {
    // もう設計図があるなら、アクセント句だけ取り直す
    const accentPhrases = await actions.FETCH_ACCENT_PHRASES({ text: yomi, ... });
    mutations.COMMAND_CHANGE_AUDIO_ITEM_TEXT({ audioKey, text, accentPhrases });
  } else {
    // はじめてなら、設計図をまるごと注文する
    const query = await actions.FETCH_AUDIO_QUERY({ text, ... });
    mutations.COMMAND_CHANGE_AUDIO_ITEM_TEXT({ audioKey, text, query });
  }
}

すでに設計図がある場合は、話す速さなどの調整をそのまま残すために、読み方の部分（アクセント句）だけを取り直します。読みが変わっていなければ、テキストだけを書きかえます。

05

アクセントの設計図

エンジンから届く設計図（AudioQuery）は、文を アクセント句 に分け、さらに モーラ（「コ」「ン」のような、1拍ぶんの音）に分けたものです。

エディターの「アクセント」欄では、accent の数字だけを変えます。数字を変えると、エディターはエンジンに POST /mora_data を注文して、新しいアクセントに合う高さと長さを計算しなおしてもらいます。

さわってみよう

言葉を選んで、モーラをクリックしてみよう。クリックした拍の あとで声が下がる 線になります（エディターのアクセント欄と同じ描き方）。

コードで見ると：アクセントの線は「if 文」で決まるcomponents/Talk/AudioAccent.vue 
// アクセント欄の線を描くところ（短くしたもの）
// accent は 1 〜 モーラの数。高い拍は y = 5、低い拍は y = 45
const points = moras.map((mora, index) => {
  const isHigh = index + 1 == accent || (index != 0 && index < accent);
  return { x: index * 40 + 10, y: isHigh ? 5 : 45 };
});

「1拍目は低い。ただし accent が 1 なら1拍目だけ高い」「2拍目から accent 拍目までは高い」「そのあとは低い」という東京式アクセントのきまりを、1行の条件で書いています。実際の高さの数字（pitch）は、エンジンが計算します。

06

エンジンとの会話

エディターとエンジンの会話は、Web API です。どんな注文ができるかは、エンジンが公開している説明書（openapi.json）に書いてあります。

📜

注文票は自動で作る

openapi.json から、注文するための TypeScript のコード（src/openapi/）を道具で生成します。手で書かないので、書きまちがいが起きにくいです。

🧩

エンジンは何個でも

VVPP というファイルでエンジンを追加できます。エンジンごとに ID と接続先（ポート）を持っていて、注文のたびに相手を選びます。

🤖

にせものエンジン

テストやブラウザ版のために、エディターの中で動く「モックエンジン」も用意されています（src/mock/）。

コードで見ると：エンジンが起きるまで待つ「for 文」store/engine.ts 
// START_WAITING_ENGINE（短くしたもの）
for (let i = 0; i < 100; i++) {
  try {
    const engine = await actions.INSTANTIATE_ENGINE_CONNECTOR({ engineId });
    await engine.invoke("version")({});   // GET /version
  } catch {
    await new Promise((resolve) => setTimeout(resolve, 1000)); // 1 秒待つ
    continue;                                             // もう一度
  }
  mutations.SET_ENGINE_STATE({ engineId, engineState: "READY" });
  break;                                                  // 返事が来たら終わり
}

エンジンは起動に少し時間がかかるので、返事が来るまで 1 秒おきに声をかけます。100 回たずねても返事がなければ「起動に失敗した」状態にします。

07

元に戻すしくみ

Ctrl+Z で元に戻せるのは、記録係がノートを書きかえるたびに 「どこをどう変えたか」のメモ を残しているからです。

コードで見ると：変更を「パッチ」として記録するstore/command.ts 
// createCommandMutation（短くしたもの）
(state, payload) => {
  // immer で「変更」と「その逆の変更」を同時に作る
  const [, redoPatches, undoPatches] = immer.produceWithPatches(
    state,
    (draft) => recipe(draft, payload),
  );
  applyPatches(state, redoPatches);               // 変更する
  state.undoCommands[editor].push({ redoPatches, undoPatches }); // 山に積む
  state.redoCommands[editor].splice(0);           // やり直す山は空に
};

名前が COMMAND_ で始まる変更は、すべてこのしくみを通ります。Ctrl+Z では山のいちばん上のメモから undoPatches を取り出して当てるだけです。

09

歌わせるしくみ

ソングでは、楽譜の音符（ノート）を 休符のところで区切って「フレーズ」 にし、フレーズごとに 4つの注文をしてから歌声を作ります。

📸

スナップショット

作っている最中に楽譜が変わっても混乱しないように、作りはじめる前に楽譜の写しをとって、それをもとに作ります。

🎚️

手で直したところ

ピッチや音量を手で描きかえたところは、エンジンが作った値の上に重ねて使います。

🎹

鳴らすのはブラウザ

できた歌声は Web Audio API で並べて鳴らします。トラックごとの音量や左右のバランスもここで調整します。

10

保存と書き出し

作業の保存は プロジェクトファイル（.vvproj）、声の保存は 音声ファイル（.wav） です。プロジェクトファイルの中身は、トークとソングの両方が入った JSON です。

プロジェクトファイルは古いバージョンで作ったものも読めるように、読みこむときに今の形へ順番に変換（マイグレーション）してから使います。

さわってみよう

書き出すファイルの名前は、タグを使ったパターンで決められます（設定 → 書き出しファイル名パターン）。エディターと同じきまりで名前を作ってみよう。

テキストは 10 文字をこえると 9 文字＋「…」に切りつめられます。ファイル名に使えない記号（\ / : * ? " < > | など）は消されます。$連番$ はかならず必要です。

コードで見ると：タグの置きかえは正規表現 1 本store/utility.ts 
// replaceTag（短くしたもの）
// $テキスト$ のような「$ と $ にはさまれた部分」を探して置きかえる
template.replace(/\$(.+?)\$/g, (match, tagName) => {
  const tagId = replaceTagStringToTagId[tagName];  // "テキスト" → "text"
  if (tagId == undefined) return match;            // 知らないタグはそのまま
  return replacer[tagId] ?? "";
});

知らないタグはそのまま残るので、設定画面は「できあがった名前に $ が残っていたらエラー」と判定しています。

11

安全のしくみ

画面の部分は Web の技術で動いているので、画面からパソコンを自由にさわれない ように、裏方係との間に「受付」をはさんでいます。

🔒

アプリの鍵（Fuses）

配布するアプリでは、Node.js として動かすモードや、外からデバッグ用の設定を入れるしくみを、ビルドのときに切っておきます。

🧭

知らない場所に行かない

画面の中のリンクは、http か https のときだけいつものブラウザで開きます。アプリの画面がほかのページに移動することはありません。

🧪

テストで見張る

部品ごとのテスト（Vitest）、アプリを実際に操作するテスト（Playwright）、画面の見た目の比較を、変更のたびに自動で動かします。

コードで見ると：リンクの開き方を決めているところbackend/electron/main.ts 
// 短くしたもの
contents.setWindowOpenHandler(({ url }) => {
  const { protocol } = new URL(url);
  if (protocol.match(/^https?:/)) {
    void shell.openExternal(url);   // いつものブラウザで開く
  }
  return { action: "deny" };         // アプリの中には新しい窓を作らない
});

contents.on("will-navigate", (event) => {
  // 開発中の再読みこみ（同じ URL）以外の移動は止める
  if (contents.getURL() !== event.url) event.preventDefault();
});

13

ことば

エディター
画面を表示して操作を受けとるプログラム。このリポジトリ
エンジン
文や楽譜を受けとって声を作る Web サーバー
AudioQuery
声を作るための設計図。アクセント句の列と、話速などの調整値
アクセント句
ひとまとまりの高低で読まれる区切り。モーラの列とアクセント位置を持つ
モーラ
1拍ぶんの音。「コ」「ン」「ニ」など。子音・母音・高さを持つ
スタイル
同じキャラクターの声の種類（ノーマル・あまあま など）
ストア（Vuex）
アプリの状態と、それを変える処理を集めた場所
メインプロセス
Electron で最初に動くプログラム。ファイルやエンジンをあつかう
レンダラープロセス
ウィンドウの中身を表示するプログラム。Vue が動く
IPC
メインプロセスとレンダラープロセスの間の連絡
キャッシュ
一度作ったものをとっておき、次から使い回すこと
ストリーミング
データを少しずつ受けとり、届いたぶんから使うこと
フレーズ
ソングで、休符で区切った音符のまとまり。歌声を作る単位
VVPP
エンジンを追加するためのファイル形式
マイグレーション
古い形のデータを、新しい形に順番に変換すること
モック
テスト用のにせもの。本物のエンジンのかわりに使う
